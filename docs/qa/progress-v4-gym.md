# Progress v4 — real gym QA plan

This checklist is deliberately built around genuine Forge usage. Do not create fake workouts, sets, PBs or weigh-ins just to make the dashboard look populated.

## Before the first gym test

1. Install a preview build from `feature/progress-v4` only after automated TypeScript / Expo Doctor / Android export checks are green.
2. Decide whether the device's existing Forge tracking data is disposable:
   - if it contains only old demo/test history, use **Reset tracking** once so V4 starts from a genuinely empty analytics state;
   - if it contains any real workout or weigh-in history you want to keep, **do not reset it**. V4 intentionally does not guess which historical rows are synthetic.
3. After a clean reset, confirm Progress shows intentional empty states rather than fabricated charts.
4. Add your actual current bodyweight through the normal Forge flow. Confirm only that real weigh-in appears on Progress.

## Empty-state pass

Before logging the first workout, verify:
- Training consistency: no completed workouts message.
- Strength progression: asks for completed weighted working sets.
- Bodyweight: empty if no genuine weigh-in exists.
- Recent PBs: no PBs in range.
- Muscle balance: no weighted volume yet.
- No hard-coded percentages, streaks, weights, dates or chart points appear.

## First real workout

Use Forge normally during a gym session.

For at least one weighted exercise:
1. Start the recommended workout.
2. Log every real working set with the actual weight and reps performed.
3. Leave at least one set incomplete temporarily and confirm it is not reflected in analytics until completed.
4. Complete the workout normally.

After finishing, open Progress and verify:
- Training consistency increases by exactly one completed workout.
- The workout does not count twice after leaving/re-entering Progress.
- The trained weighted exercise appears in the strength exercise selector.
- e1RM is based on the best completed set from that session using `weight × (1 + reps / 30)`.
- Max Weight shows the heaviest completed set from the session.
- Volume is the sum of `weight × reps` for completed weighted sets in that exercise/session.
- An incomplete/null-weight set contributes nothing to weighted volume.
- First-time PB tiles show the actual record value when there is no legitimate prior PB to compare against.
- Muscle balance reflects the real weighted volume from completed sets only.

### Quick e1RM spot-check

Pick one real completed set and calculate it independently:

`e1RM = weight × (1 + reps / 30)`

Example only for checking the formula: if a real set happens to be 15 kg × 10 reps, the calculation is 20.0 kg. Do not enter this example into Forge unless it is what you actually lifted.

## Second real session / trend pass

The strength trend becomes much more useful after a second session for the same exercise.

Verify:
- the line connects the two genuine session points in chronological order;
- the percentage change is latest session versus first in-range session;
- a negative change renders as a decrease rather than being forced positive;
- the computed insight states the real direction, percentage and session count;
- switching between e1RM / Max Weight / Volume changes the chart and headline consistently;
- selecting another eligible exercise switches to only that exercise's real session history.

## Bodyweight pass

Across genuine weigh-ins:
- the headline uses the latest in-range weight, or latest-known weight when the selected range has no entries;
- the chart itself contains only entries inside the selected range;
- the delta is first versus last weigh-in inside the range;
- a single weigh-in does not invent a trend;
- reset leaves the bodyweight chart genuinely empty until a new weigh-in is entered.

## Range selector pass

Test all four ranges after enough genuine history exists:

### 7D
- one consistency bar per local calendar day;
- only workouts/sets/weigh-ins/PBs in the trailing 7 days appear.

### 30D
- consistency is grouped into weekly buckets, including partial boundary weeks;
- sessions/week uses 30 days as the denominator, not a fabricated four-week month.

### 12W
- 12 weekly consistency bars;
- default range on a fresh screen load.

### 1Y
- consistency is grouped by calendar month;
- sparse history remains readable and does not crash.

## PB integrity pass

When a genuine new PB is achieved:
- a displayed `+x kg` / `+x reps` delta must equal the current PB minus the prior PB for that exact exercise + metric;
- if there was no prior record, show the record itself instead of inventing an improvement;
- multiple metrics generated by one set should not flood the Recent PB strip with near-duplicate tiles for the same exercise/day;
- `View all` still opens PB History.

## Muscle balance integrity pass

Spot-check at least one workout manually:
- each completed weighted set contributes `weight × reps`;
- incomplete sets contribute zero;
- bodyweight/null-weight sets contribute zero to V4 weighted volume;
- Chest + Upper chest group together as Chest;
- Lats + Upper back group together as Back;
- side/rear delts + shoulders group as Shoulders;
- biceps + triceps group as Arms;
- quads/hamstrings/glutes/calves group as Legs;
- rows sort from highest real volume to lowest.

## Visual QA against the approved mockup

Capture a physical Android screenshot after the dashboard has genuine data and compare side-by-side with the approved mockup.

Check specifically:
- `Your Progress` hierarchy;
- range pill placement and selected lime state;
- card order and compact vertical rhythm;
- blue/lime accent balance;
- chart density and point visibility;
- exercise/metric picker usability with one hand;
- labels do not collide at 7D, 12W or 1Y;
- horizontal PB strip remains usable on a narrow phone;
- muscle-volume numbers do not clip;
- final card clears the persistent tab bar;
- larger Android font scaling remains usable.

## Regression pass before merge

- Today loads and real current data remains intact.
- Train loads the recommended program.
- Exercise logging still saves sets and PBs.
- Finishing a workout still rotates the program correctly.
- Goals loads.
- PB History opens.
- Reset tracking clears workouts, sets, PBs and weights without breaking the program/exercise library.
- Exercise video/technique settings remain intact after reset.

## Merge gate

Do not mark PR #3 ready for review or merge it until:
- automated QA is green;
- a fresh Android preview build installs;
- at least one genuine gym session has flowed end-to-end into Progress;
- the physical-device screenshot has been visually compared to the approved mockup;
- any data-integrity discrepancy is resolved rather than papered over with display-only values.
